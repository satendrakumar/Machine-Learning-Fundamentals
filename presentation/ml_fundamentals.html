What is Machine Learning?

🤔 What do you think?

Let's start with the most basic question: what exactly is machine learning?

[Ask the audience] Before I show you an answer, what do you think it is? Take two or three answers.

Typical answers are "AI", "robots", "computers that think" or "ChatGPT". Acknowledge each one; they're all related. Then say: let's pin down what it actually means.

So, What Is Machine Learning?

Machine learning is teaching computers to learn from examples, instead of programming every rule by hand.

📚 Learn

Look at lots of past examples, e.g. transactions marked fraud or genuine

🔍 Find patterns

Work out the rules that connect inputs to answers. These rules are the model

🎯 Predict

Use those rules to give answers for new data it has never seen

"The field of study that gives computers the ability to learn without being explicitly programmed." — Arthur Samuel, 1959

Here's a simple definition: machine learning is teaching computers to learn from examples, instead of programming every rule by hand.

[Click] It comes down to three steps. Learn: the computer looks at lots of past examples, such as transactions already labelled fraud or genuine. Find patterns: it works out the rules connecting the inputs to the answers, and those learned rules are what we call a model. Predict: it uses that model on new data it has never seen.

[Click] This idea is old. Arthur Samuel, who built a checkers program that learned to beat him, described it this way back in 1959.

Link back to the audience's answers: AI is the broad goal of making machines smart, and machine learning is the most successful way we've found to get there.

Traditional Programming vs Machine Learning

Instead of writing the rules ourselves, we show the computer many examples with answers, and it figures out the rules on its own.

In traditional programming, a developer writes the rules. For example: "if the amount is above 1 lakh and the country is new, flag the transaction". Data goes in, rules are applied, answers come out.

[Click] In machine learning we flip it around. We give the computer data AND the correct answers, for example thousands of past transactions labelled fraud or genuine, and it works out the rules by itself. Those learned rules are what we call a model.

Why does this matter? Some rules are too complex to write by hand. Nobody can write rules to recognise a face, but a model can learn them from examples.

Three Main Types of Machine Learning

There are three broad families.

Supervised learning: we have labelled examples, like questions with an answer key. This is by far the most common in industry and it's our focus today. It splits into two kinds: classification and regression.

Unsupervised learning: no labels; the model finds structure by itself, e.g. grouping customers into segments.

Reinforcement learning: an agent learns by trial and error with rewards. Game-playing AI and robotics use it.

The Machine Learning Workflow

We split data into a training set (to learn from, ~80%) and a test set (to check on unseen data, ~20%) — like practice questions vs. the final exam.

Every ML project follows roughly these six steps. Collect data, clean it (honestly this is often 70 to 80 percent of the work), choose a model, train it, evaluate it, and deploy it.

The red dashed arrow matters: it's an iterative loop. If evaluation is poor, we go back and try a different model or better features.

Key point: we always keep a test set the model never sees during training. It's like keeping the final exam paper hidden while students practise. Otherwise we'd only be measuring memorisation.

Regression

Predicting a number

Let's start with the simplest type of supervised learning: regression.

What Is Regression?

Regression answers "How much?" or "How many?" — the output is a continuous number.

🏠

House price from area, location, age

💰

Customer's monthly spending

🌡️

Tomorrow's temperature

📈

Next month's sales

If the answer can be 54.3, 54.31 or 54.312 — any value on a number line — it's a regression problem.

Regression answers "how much?" or "how many?". The output is a number on a continuous scale.

House prices, customer spending, temperature, sales forecasts.

A simple test: if the answer can have decimals and any value in between makes sense, it's regression.

Linear Regression: Fit a Straight Line

$$\hat{y} = {\color{#f59e0b} w}\,{\color{#2563eb} x} + {\color{#f59e0b} b}$$
  • $x$ — input (area)
  • $\hat{y}$ — prediction ("y-hat")
  • $w$ — weight / slope: how much price rises per sq ft
  • $b$ — bias / intercept: base price

Learning = finding the w and b that make the line pass as close as possible to all the dots.

The simplest regression model is a straight line: y-hat equals w times x plus b. It's the same as y equals m x plus c from school.

x is the input, area. w is the weight, the slope: how much the price goes up per square foot. b is the bias, the starting price.

[Click to draw the line] Learning simply means finding the w and b that make the line fit the blue dots as closely as possible.

The words "weight" and "bias" will come back when we get to neural networks. They're exactly the same idea.

Worked Example

Suppose training found: $w = 0.05$ lakh per sq ft and $b = 10$ lakh.

$$\hat{y} = 0.05 \times {\color{#2563eb}1000} + 10 = {\color{#16a34a}60 \text{ lakh}}$$

A 1000 sq ft house → predicted price ₹60 lakh.

More than one feature? Just add more terms

$$\hat{y} = {\color{#f59e0b}w_1}{\color{#2563eb}x_1} + {\color{#f59e0b}w_2}{\color{#2563eb}x_2} + {\color{#f59e0b}w_3}{\color{#2563eb}x_3} + {\color{#f59e0b}b}$$
$$\hat{y} = 0.05\cdot\underbrace{1200}_{\text{area}} + 5\cdot\underbrace{3}_{\text{bedrooms}} - 0.8\cdot\underbrace{10}_{\text{age}} + 10 = 60 + 15 - 8 + 10 = {\color{#16a34a}77\text{ lakh}}$$

Each feature gets its own weight. A negative weight (age) means "more of this → lower price".

Say training gave us w equals 0.05 lakh per square foot and b equals 10 lakh. A 1000 square foot house: 0.05 times 1000 is 50, plus 10, gives 60 lakh.

[Click] Real problems have many features, so we just add a term per feature, each with its own weight.

Walk through the example: 1200 square feet gives 60, 3 bedrooms at 5 lakh each gives 15, age 10 years at minus 0.8 gives minus 8, plus the base of 10, which totals 77 lakh.

Point out the negative weight on age: the model learned older houses are cheaper. The weights tell us how each feature affects the prediction.

How Wrong Is Our Line? Residuals

For each point, the error (residual) is the gap between the real value and the prediction:

$$\text{error}_i = y_i - \hat{y}_i$$

The red lines show how far off we are. A good model makes these lines short. To compare models we need one number that sums up all the red lines — that's a loss function.

No line passes through every point perfectly. The red vertical lines are the residuals or errors: actual value minus predicted value.

Some errors are positive (point above the line), some negative (below).

To decide which line is "best" we need to boil all these red lines down into a single score. That score is called a loss function, which is our next section.

03

Loss Functions

One number that says "how wrong" the model is

Loss functions: how a model knows how wrong it is.

What Is a Loss Function?

  • A formula that compares predictions with true answers
  • Outputs a single number: the loss
  • Lower = better. Perfect predictions → loss of 0
  • Training = adjusting weights to make the loss smaller

The loss is the model's "score" in a game where the goal is to get as low as possible — like golf.

A loss function compares predictions with the true answers and gives back one number.

Think of it like golf or darts: lower is better, and a perfect score is zero.

This is the single most important idea in the session: training a model means changing its weights to make the loss smaller. Everything else, including backprop and optimizers, is just machinery to do that efficiently.

Mean Squared Error (MSE) — for Regression

$$\text{MSE} = \frac{1}{n}\sum_{i=1}^{n}\big({\color{#16a34a}y_i} - \hat{y}_i\big)^2$$

take each error → square it → average them

$$\text{MSE} = \frac{100 + 400 + 0}{3} \approx {\color{#dc2626}166.7}$$

Squaring makes every error positive (so −10 and +10 don't cancel) and punishes big mistakes much more than small ones.

The most common regression loss is Mean Squared Error. Three steps: take each error, square it, average them.

Walk through the table: errors of minus 10, plus 20 and 0. Squared, that's 100, 400 and 0. The average is about 166.7.

Why square? Two reasons. First, it makes everything positive so errors don't cancel out: minus 10 and plus 10 would otherwise add to zero. Second, it punishes big mistakes far more: an error of 20 counts four times as much as an error of 10, not twice.

MSE vs MAE — How They Treat Outliers

$$\text{MAE} = \frac{1}{n}\sum |y_i - \hat{y}_i|$$

Mean Absolute Error just averages the size of the errors (no squaring).

Errors: 1, 1, 1, 10 (one outlier)

RMSE $= \sqrt{\text{MSE}}$ brings the units back to the original scale — easier to explain: "we're off by about ₹12.9 lakh on average".

The alternative is Mean Absolute Error: just average the size of the errors, with no squaring.

Example: errors 1, 1, 1 and one outlier of 10. MAE is 3.25, but MSE jumps to 25.75 because that 10 becomes 100 when squared.

So MSE is very sensitive to outliers. Use it when big errors are truly bad. MAE is more robust if your data has a few weird values.

RMSE, the square root of MSE, is handy for reporting because it's back in the original units, like rupees.

The Loss Landscape

If we try every possible weight $w$ and plot the loss, MSE gives a nice bowl shape.

Training = rolling down to the bottom of the bowl, where the loss is smallest. How we roll down is called optimization (section 8).

Imagine trying every possible value of the weight w and plotting the loss for each. For MSE we get a smooth bowl.

We start at a random weight, the blue dot, and want to reach the bottom, the green dot, where the loss is smallest.

How we roll down this bowl efficiently is the topic of optimization, which comes in the last section. Keep this picture in mind.

Cross-Entropy — for Classification

When the model outputs a probability $p$ that the answer is "yes", we use Binary Cross-Entropy (log loss):

$$L = -\big[\,y\log(p) + (1-y)\log(1-p)\,\big]$$

If the true answer is yes ($y=1$), this simplifies to $L = -\log(p)$:

Cross-entropy rewards being confident and right, and heavily punishes being confident and wrong.

For classification the model outputs a probability, so we use a different loss: cross-entropy, also called log loss.

When the true answer is yes, it simplifies to minus log of p, where p is the probability the model gave to "yes".

Look at the table: 90 percent confident and right gives a tiny loss of 0.11. Unsure at 50 percent gives 0.69. But 10 percent, which means confident and WRONG, gives 2.30, a big penalty.

The curve shows it shoots up towards infinity as p approaches 0. Cross-entropy strongly discourages being confidently wrong.

Logistic Regression: Turning Scores into Probabilities

Step 1 — compute a score, exactly like linear regression:

$$z = {\color{#f59e0b}w_1}{\color{#2563eb}x_1} + {\color{#f59e0b}w_2}{\color{#2563eb}x_2} + {\color{#f59e0b}b}$$

Step 2 — squash it into a probability between 0 and 1 using the sigmoid:

$$p = \sigma(z) = \frac{1}{1 + e^{-z}}$$

Step 3 — decide: if $p \ge 0.5$ → Spam, else Not spam

The classic classifier is logistic regression. Despite the name, it's used for classification.

Step 1: compute a score z exactly like linear regression. This score can be any number, minus 50 or plus 300.

Step 2: squash it into a probability between 0 and 1 using the sigmoid function. Look at the S-curve: large negative z gives almost 0, large positive gives almost 1, and z of 0 gives exactly 0.5.

Step 3: apply a threshold, usually 0.5: above it is spam, below it is not spam.

Worked Example: Is This Email Spam?

Learned weights: $w_1 = 1.5$ (per "FREE"), $w_2 = 0.8$ (has link), $b = -2$

New email: the word "FREE" appears 2 times and it contains a link (1).

$$z = 1.5 \times {\color{#2563eb}2} + 0.8 \times {\color{#2563eb}1} + (-2) = 3 + 0.8 - 2 = 1.8$$
$$p = \sigma(1.8) = \frac{1}{1 + e^{-1.8}} = \frac{1}{1 + 0.165} \approx {\color{#dc2626}0.86}$$

The model is 86% sure this email is spam. 0.86 ≥ 0.5, so it goes to the spam folder.

Let's do it with numbers. The weights are 1.5 for each "FREE", 0.8 for having a link, and a bias of minus 2.

The email has 2 "FREE"s and a link. So z is 3 plus 0.8 minus 2, which is 1.8.

[Click] Sigmoid of 1.8: e to the minus 1.8 is about 0.165, so 1 over 1.165 is about 0.86.

[Click] The model is 86 percent sure it's spam. That's above 0.5, so it goes to the spam folder.

Classification comes in three flavours, and it's important to recognise which one you have.

Binary: two classes, pick one. Spam or not.

Multiclass: three or more classes, still pick exactly one. A photo is a cat OR a dog OR a rabbit.

Multilabel: many labels, and any number can be true at once. A movie can be Action AND Sci-Fi; a photo can be tagged beach AND sunset AND people.

Ask: "Is classifying a customer complaint into a department multiclass or multilabel?" It depends: can one complaint belong to several departments?

Multiclass: The Softmax Function

The model produces one raw score $z_k$ per class. Softmax turns them into probabilities that add up to 1:

$$p_k = \frac{e^{z_k}}{\sum_{j=1}^{K} e^{z_j}}$$

For multiclass, the model produces one raw score per class. Softmax turns these into probabilities that add up to exactly 1.

Recipe: raise e to the power of each score, then divide each by the total.

Walk through: scores 2, 1 and 0.1 become 7.39, 2.72 and 1.11. The total is 11.21, so the probabilities are 66, 24 and 10 percent.

Think of it as a competition: the classes share 100 percent between them. The prediction is the class with the biggest share: cat.

Multilabel: Independent Yes/No for Each Label

Each label gets its own sigmoid — a separate yes/no question. Probabilities do not need to sum to 1.

$$p_k = \sigma(z_k) = \frac{1}{1+e^{-z_k}} \quad \text{for each label } k$$

Movie: "Interstellar" (threshold 0.5)

The movie is tagged Action + Sci-Fi + Romance. The sum is 2.45 — that's fine, because each label is decided independently.

For multilabel, there's no competition. Each label gets its own sigmoid: a separate yes/no question.

For Interstellar: Action 0.92 yes, Comedy 0.15 no, Sci-Fi 0.81 yes, Romance 0.57 yes.

The probabilities add up to 2.45, more than 1. That's perfectly fine because each label is decided independently.

This is the key difference from softmax.

05

Evaluating a Classifier

Accuracy, confusion matrix, precision, recall, F1

We've built a classifier. How do we know whether it's any good? This section is the one people get wrong most often in practice.

The Accuracy Trap 🪤

A bank has 1,000 card transactions. Only 10 are fraud.

A "lazy" model predicts "Genuine" for every single transaction.

$$\text{Accuracy} = \frac{990 \text{ correct}}{1000} = {\color{#16a34a}99\%}$$

99% accurate… yet it catches zero fraud cases! When classes are imbalanced, accuracy alone is misleading. We need to look at which kinds of mistakes the model makes.

Here's a puzzle. 1,000 transactions, only 10 are fraud. A lazy model says "genuine" every time.

Ask the audience: "What's its accuracy?" Answer: 990 out of 1000, which is 99 percent!

[Click] But it catches zero fraud. It's completely useless, even though 99 percent sounds great.

This happens whenever classes are imbalanced, which is very common: fraud, disease and defects are all rare. We need metrics that look at the kinds of mistakes.

The Confusion Matrix

A table that counts the 4 possible outcomes:

  • TP — True Positive: said yes, was yes ✅
  • TN — True Negative: said no, was no ✅
  • FP — False Positive: said yes, was no ❌ "false alarm"
  • FN — False Negative: said no, was yes ❌ "missed it"

The first word (True/False) tells you if the model was right. The second word is what the model predicted.

The confusion matrix counts four outcomes.

True Positive: we said yes and it was yes; we caught it. True Negative: we said no and it was no.

False Positive: we said yes but it was no, a false alarm. False Negative: we said no but it was yes, we missed it.

Memory trick: the second word (Positive or Negative) is what the model predicted. The first word (True or False) says whether that prediction was right.

Real Example: A COVID Test on 100 People

  • 10 people are really sick, 90 are healthy
  • Test caught 8 sick people (TP)
  • Test missed 2 sick people (FN)
  • Test wrongly flagged 5 healthy people (FP)
  • Test correctly cleared 85 healthy people (TN)

We'll compute every metric from these 4 numbers.

Let's make it concrete. 100 people take a test. 10 are really sick and 90 are healthy.

The test catches 8 of the sick (TP) and misses 2 (FN). Among the healthy, it wrongly flags 5 (FP) and correctly clears 85 (TN).

We'll compute every metric from these four numbers: 8, 2, 5 and 85.

Accuracy & Precision

Accuracy

$$\frac{TP + TN}{TP + TN + FP + FN} = \frac{8 + 85}{100} = {\color{#16a34a}93\%}$$

Out of everyone, how many did the test get right?

Precision

$$\frac{TP}{TP + FP} = \frac{8}{8 + 5} = {\color{#f59e0b}61.5\%}$$

When the test says "sick", how often is it right? Only ~6 out of 10 positive results are real.

Precision focuses on the Predicted Positive column: "Can I trust a positive result?" High precision = few false alarms.

Accuracy: correct predictions over everything. 8 plus 85 is 93 out of 100: 93 percent. Sounds good.

Precision: of everyone the test called sick, how many really were? 8 out of 13 positives is about 61.5 percent.

So if you test positive, there's only about a 6-in-10 chance you're actually sick. Precision answers: "Can I trust a positive result?"

Recall & F1 Score

Recall (Sensitivity)

$$\frac{TP}{TP + FN} = \frac{8}{8 + 2} = {\color{#2563eb}80\%}$$

Out of all truly sick people, how many did we catch? We found 8 of 10.

F1 Score

$$F_1 = 2 \cdot \frac{P \cdot R}{P + R} = 2 \cdot \frac{0.615 \times 0.8}{0.615 + 0.8} = {\color{#7c3aed}69.6\%}$$

A single score that balances precision and recall. It's high only when both are high.

Why not a simple average? If P = 100% and R = 1%, average = 50.5% (looks OK!) but F1 = 2% — the harmonic mean exposes the weak side.

Recall, also called sensitivity: of everyone who was really sick, how many did we catch? 8 out of 10 is 80 percent.

F1 combines precision and recall into one number using the harmonic mean. Here it's about 69.6 percent.

Why the harmonic mean? It punishes imbalance. Precision 100 percent with recall 1 percent has a simple average of 50.5, which looks fine, but an F1 of only 2 percent, which tells you the truth. F1 is only high when BOTH are high.

Precision or Recall? It Depends on the Cost of Mistakes

Favour Precision when false alarms hurt

  • 📧 Spam filter — sending your job offer to spam is worse than letting one spam through
  • 🔍 Search results — top results must be relevant
  • ⚖️ Auto-blocking a customer account — don't lock out genuine users

Favour Recall when misses hurt

  • 🏥 Cancer screening — missing a patient is dangerous; extra tests are OK
  • 💳 Fraud detection — missing fraud costs money; a quick verification call is cheap
  • ✈️ Airport security — better to check a few extra bags

Ask: "Which is worse — a false alarm (FP) or a miss (FN)?" Use F1 when both matter.

Which matters more depends on what a mistake costs.

Favour precision when false alarms hurt: a spam filter that hides your job offer, or blocking a genuine customer's account.

Favour recall when misses hurt: cancer screening, where missing a patient can be fatal, or fraud detection, where a quick verification call costs far less than a missed fraud.

Ask the audience: "For a loan default model, which matters more?" Discuss: missing a defaulter costs money, but rejecting good customers loses business. Often you balance with F1.

The Precision–Recall Trade-off

Moving the decision threshold changes which emails are flagged:

high recall, more false alarms → lower precision high threshold (0.8) only flag sure cases → high precision, miss some spam → lower recall spam not spam

You can't usually max out both. Raising the threshold trades recall for precision, and lowering it does the opposite.

The model outputs a probability, and we choose the threshold.

Low threshold, say 0.3: we flag almost everything suspicious, catch all the spam (high recall), but get more false alarms (lower precision).

High threshold, say 0.8: we only flag cases we're sure about (high precision), but some spam slips through (lower recall).

You can't usually max out both. Choosing the threshold is a business decision as much as a technical one.

Neural Networks

Neurons, perceptrons, hidden layers, activation functions, parameters & tuning

Now the second half: neural networks, the technology behind image recognition, speech and large language models.

Inspired by the Brain

Neural networks are loosely inspired by the brain. A biological neuron receives signals through dendrites, and if the combined signal is strong enough, it fires a signal down its axon.

An artificial neuron copies the idea: inputs come in, each is multiplied by a weight (how important it is), they're summed with a bias, and an activation function decides the output.

A small honesty note: it's an inspiration, not a simulation. Real neurons are far more complex.

What a Single Neuron Computes

$$z = \sum_{i=1}^{n} {\color{#f59e0b}w_i}\,{\color{#2563eb}x_i} + {\color{#f59e0b}b} \qquad\qquad a = f(z)$$
  1. Multiply each input by its weight (how important is it?)
  2. Add them up, plus a bias (a baseline nudge)
  3. Pass through an activation function $f$ (decide how strongly to "fire")

Example: $x = (2, 3)$, $w = (0.5, -1)$, $b = 1$: $\; z = 0.5(2) + (-1)(3) + 1 = -1$, and with ReLU $a = \max(0, -1) = 0$ → the neuron stays quiet.

A neuron is just a weighted vote followed by a decision. Linear regression is a neuron with no activation function!

The neuron does three things: multiply each input by its weight, add them up plus the bias, then pass the result through an activation function.

Example: inputs 2 and 3, weights 0.5 and minus 1, bias 1. z is 1 minus 3 plus 1, which is minus 1. With ReLU, a negative becomes 0, so the neuron stays quiet.

Notice the first part is exactly linear regression. A neuron is linear regression plus a decision step.

The Perceptron (1958) — The First Neuron

Uses a step function: output is 1 if $z \ge 0$, else 0.

$$\hat{y} = \begin{cases} 1 & \text{if } w_1x_1 + w_2x_2 + b \ge 0 \\ 0 & \text{otherwise} \end{cases}$$

Learning rule: for each mistake, nudge the weights toward the right answer:

$$w_i \leftarrow w_i + \eta\,(y - \hat{y})\,x_i$$

$\eta$ (eta) = learning rate, a small step size like 0.1

Example: an AND gate with $w_1 = w_2 = 1,\ b = -1.5$

The perceptron was invented by Frank Rosenblatt in 1958. It's the original artificial neuron, using a step function that outputs 1 or 0.

Its learning rule is simple: when it's wrong, nudge each weight in the direction that would have made it right, scaled by a learning rate.

A Neural Network = Layers of Neurons

Early layers find simple patterns; later layers combine them into complex ones (edges → shapes → faces). "Deep learning" = many hidden layers.

A neural network is many neurons organised in layers.

The input layer is just the features, with no computation. Hidden layers in the middle do the learning. The output layer gives the prediction.

Every neuron is connected to every neuron in the next layer. This is called a fully connected or dense network, and each grey line is one weight.

"Deep learning" simply means many hidden layers.

What Do Hidden Layers Actually Do?

They're called hidden because we never see their values in the data. We only see the inputs and the final output. Each hidden layer turns its inputs into new, more useful features.

🏦 Fraud example: one hidden neuron may learn "large amount + new merchant", another "transaction at 3 a.m. from a new country". The output layer combines these clues into a fraud score.

Why are they called "hidden"? Because their values aren't in our data. We only see inputs and outputs, and the hidden layers work things out in between.

Each hidden layer builds new features out of the previous layer's outputs. In face recognition, the first layer learns edges, the next combines edges into shapes like eyes and noses, and the output combines those into "face".

Nobody programs "detect an eye". The network discovers these features by itself during training.

The banking example: hidden neurons may learn combinations like "large amount plus new merchant", which the output layer combines into a fraud score.

Why Do We Need Activation Functions?

Without them, two layers collapse into one:

$$W_2(W_1x + b_1) + b_2 = \underbrace{(W_2W_1)}_{W'}x + \underbrace{(W_2b_1 + b_2)}_{b'}$$

Still just a straight line, no matter how many layers you stack! 😕

With a non-linear activation between layers, each neuron adds a "bend". Lots of bends combined can trace any curve.

The activation function is the neuron's "decision": how strongly should I fire for this input? It's what lets networks learn curvy, real-world patterns.

Now, activation functions. Why do we need them at all?

Without them, each layer is just a multiply and an add. Stack two such layers and the math collapses: W2 times W1 is just another matrix. So 100 layers without activations are no more powerful than one: still a straight line.

Non-linear activations add a "bend" at each neuron. Combine many bends and you can approximate any curve, as the right-hand picture shows: straight ReLU pieces joining to trace a curved pattern.

Sigmoid squashes any number into 0–1, like a dimmer switch. Great for a final "yes/no probability", but too slow to learn with inside deep networks.

Sigmoid squashes any input into the range 0 to 1, so the output reads as a probability. That's why it's used in the output layer for binary and multilabel problems.

Look at the table: minus 5 gives almost 0, 0 gives 0.5, plus 5 gives almost 1.

The downside is the vanishing gradient. The circled flat regions have almost zero slope, and even the steepest part has a slope of only 0.25. During backprop these slopes multiply layer after layer: 0.25 to the fifth power is about 0.001. Early layers get almost no learning signal. That's why sigmoid is rarely used in hidden layers today.

Same S-shape as sigmoid, but stretched from −1 to +1, so a neuron can say "strongly no", "neutral" or "strongly yes".

Tanh is the same S-shape, stretched to go from minus 1 to plus 1, and centred at zero.

Being zero-centred means outputs are both positive and negative, which generally makes training faster than sigmoid.

It's still common inside recurrent networks such as LSTMs and GRUs. But it also flattens at the ends, so the vanishing gradient problem remains.

$$\text{ReLU}(z) = \max(0,\ z) \qquad \text{range: } [0,\ \infty)$$

✅ Very fast — just "if negative, make it 0"

ReLU is a one-way gate: negative signals are blocked and positive signals pass through unchanged. Simple, fast, and it works, so it's the first choice for hidden layers.

ReLU, the Rectified Linear Unit, is the workhorse of modern deep learning. The rule couldn't be simpler: if the input is negative, output 0; otherwise pass it through unchanged.

Why is it so popular? It's extremely cheap to compute, and for positive inputs the slope is exactly 1, so gradients don't shrink as they flow back. This is a big part of why very deep networks became trainable around 2010 to 2012.

One weakness: "dying ReLU". If a neuron's input is always negative, it always outputs 0 and its gradient is 0, so it stops learning forever. Leaky ReLU fixes this with a tiny slope for negatives. GELU and SiLU are smooth variants used in Transformers like GPT.

Softmax — Picking One Class Out of Many

$$\text{softmax}(z)_k = \frac{e^{z_k}}{\sum_j e^{z_j}}$$
  • Applied to the whole output layer, not to one neuron
  • Every output is between 0 and 1, and they add up to 1
  • $e^{z}$ makes the largest score stand out even more ("soft" version of picking the max)
  • Use in the output layer for multiclass problems, paired with categorical cross-entropy

Softmax is a vote where the classes share 100% of the probability. Raising one class's share must lower the others.

We met softmax in classification. In a neural network it sits on the output layer for multiclass problems.

Unlike the others, it isn't applied to each neuron separately. It looks at all output scores together and turns them into probabilities that sum to 1.

The exponential exaggerates differences, so the largest score gets a bigger share. That's why it's called a "soft" max: it mostly picks the winner but keeps some probability for the others.

It's always paired with categorical cross-entropy loss.

Spotting Overfitting: Training vs Validation Loss

Hold back a validation set the model never trains on.

  • Training loss keeps falling
  • Validation loss falls, then rises → the model has started memorising

Early stopping: stop training (and keep the weights) at the point where validation loss is lowest.

How do we detect overfitting in practice? Keep a validation set aside and track both losses during training.

At first both go down: the model is learning real patterns. Then at some point validation loss starts going UP while training loss keeps falling. That's the moment the model starts memorising.

Early stopping: stop training at the lowest validation loss and keep those weights. It's simple and very effective.

Feedforward & Backpropagation

How a network makes predictions — and how it learns from mistakes

Now the heart of it: how does a neural network actually learn? Two phases: feedforward to predict, and backpropagation to learn from the error.

The Training Loop

Training is a loop of four steps, repeated thousands or millions of times.

One: feedforward, pushing inputs through the network to get a prediction. Two: compute the loss, how wrong we were. Three: backpropagation, working out how much each weight contributed to the error. Four: update the weights a little using an optimizer.

Then repeat with the next batch. After all batches, one epoch is done, and we run many epochs.

Feedforward: Data Flows Forward

Each layer $l$ does the same neuron computation on the previous layer's outputs:

$$\mathbf{a}^{(l)} = f\!\left(\mathbf{W}^{(l)}\,\mathbf{a}^{(l-1)} + \mathbf{b}^{(l)}\right)$$

Feedforward is simply "make a prediction": push the inputs through each layer in turn until an answer comes out the other end.

Feedforward simply means making a prediction. Data flows left to right, layer by layer.

Each layer does the same neuron computation we've seen, just for many neurons at once using a matrix: multiply by the weights, add the bias, apply the activation.

The output of one layer becomes the input of the next, until we get the prediction and compare it to the truth with the loss.

Worked Example — Forward Pass

One sigmoid neuron. Inputs $x_1 = 1,\ x_2 = 2$; weights $w_1 = 0.5,\ w_2 = -0.3$; bias $b = 0.1$. True answer $y = 1$.

$$z = 0.5(1) + (-0.3)(2) + 0.1 = 0$$
$$\hat y = \sigma(0) = 0.5$$
$$L = (y - \hat y)^2 = (1 - 0.5)^2 = {\color{#dc2626}0.25}$$

The model is only 50% sure when the answer is definitely 1. We need to adjust the weights.

Let's follow real numbers through one sigmoid neuron. Inputs 1 and 2, weights 0.5 and minus 0.3, bias 0.1. The true answer is 1.

z is 0.5 minus 0.6 plus 0.1, which is exactly 0. Sigmoid of 0 is 0.5.

Loss: 1 minus 0.5 squared is 0.25.

The model is sitting on the fence at 50 percent when the answer is definitely 1. How should we change the weights? That's what backprop tells us.

Backpropagation: Assigning the Blame

  • Start at the loss and work backwards through each layer
  • For every weight, compute its gradient $\frac{\partial L}{\partial w}$: "if I nudge this weight up a little, how much does the loss change?"
  • Positive gradient → lower the weight; negative gradient → raise it

It's like a team reviewing a lost match: the error is traced back so each player (weight) learns how much they contributed and how to adjust.

Backpropagation sends the error signal backwards from the loss through each layer.

For every weight it computes the gradient: if I nudge this weight up slightly, does the loss go up or down, and by how much?

Positive gradient means increasing the weight increases the loss, so decrease it. Negative gradient means do the opposite.

The team analogy: after losing a match, you review the game backwards from the final goal to see how much each player contributed, so each can adjust.

The Chain Rule — the Engine of Backprop

The loss depends on $w$ through a chain: $w \rightarrow z \rightarrow \hat y \rightarrow L$. So we multiply the effect of each link:

$$\frac{\partial L}{\partial w_1} = \underbrace{\frac{\partial L}{\partial \hat y}}_{\text{loss vs output}} \cdot \underbrace{\frac{\partial \hat y}{\partial z}}_{\text{activation slope}} \cdot \underbrace{\frac{\partial z}{\partial w_1}}_{\text{input } x_1}$$
LinkFormulaOur numbers
$\partial L/\partial \hat y$$-2(y - \hat y)$$-2(1-0.5) = -1$
$\partial \hat y/\partial z$$\sigma(z)(1-\sigma(z))$$0.5 \times 0.5 = 0.25$
$\partial z/\partial w_1$$x_1$$1$

Gears: if gear A turns gear B twice as fast, and B turns C three times as fast, then A turns C 2 × 3 = 6 times as fast. Backprop just multiplies these "speeds".

How do we compute these gradients? With the chain rule from calculus. Don't worry, the idea is simple.

The weight affects z, z affects the prediction, and the prediction affects the loss. It's a chain. To find the weight's effect on the loss, multiply the effect of each link.

The gears analogy: if gear A turns B twice as fast, and B turns C three times as fast, A turns C six times as fast. Just multiply.

Our numbers: loss vs prediction is minus 1, sigmoid slope is 0.25, and z vs w1 is just the input, 1.

Backprop is this chain rule applied efficiently to every weight, reusing shared parts of the computation.

Worked Example — Backward Pass & Update

Gradients (from the chain rule):

$$\frac{\partial L}{\partial w_1} = -1 \times 0.25 \times 1 = -0.25$$
$$\frac{\partial L}{\partial w_2} = -1 \times 0.25 \times 2 = -0.5$$
$$\frac{\partial L}{\partial b} = -1 \times 0.25 \times 1 = -0.25$$

Update with learning rate $\eta = 0.1$:

$$w \leftarrow w - \eta\,\frac{\partial L}{\partial w}$$
  • $w_1 = 0.5 - 0.1(-0.25) = 0.525$
  • $w_2 = -0.3 - 0.1(-0.5) = -0.25$
  • $b = 0.1 - 0.1(-0.25) = 0.125$

Forward pass again: $z = 0.15$, $\hat y = 0.537$, loss $= (1-0.537)^2 = {\color{#16a34a}0.214}$ (it was 0.25) 🎉

One step made the model a little better. Repeat this thousands of times over many examples and the network learns.

Multiply the links: the gradient for w1 is minus 0.25. For w2 it's minus 0.5, because its input was 2. For the bias it's minus 0.25.

Update rule: new weight equals old weight minus the learning rate times the gradient. With learning rate 0.1: w1 becomes 0.525, w2 becomes minus 0.25, b becomes 0.125.

[Click] Run forward again: the prediction is 0.537 and the loss is 0.214, down from 0.25. The model improved!

[Click] That's one tiny step. Real training repeats this millions of times across all weights and examples. That's all "learning" is.

Optimization

Gradient descent, SGD, Momentum, RMSProp, Adam

Final technical section: optimizers, the algorithms that decide exactly how to update the weights.

Gradient Descent: Walking Downhill Blindfolded

You're on a foggy mountain and want to reach the valley. You can only feel the slope under your feet, so you take a step in the steepest downhill direction, again and again.

$$w \leftarrow w - {\color{#7c3aed}\eta}\,{\color{#dc2626}\frac{\partial L}{\partial w}}$$

$\eta$ = learning rate (step size)  ·  gradient = slope

Imagine you're on a mountain in thick fog and want to reach the valley. You can't see, but you can feel the slope under your feet. So you step downhill, feel again, and step again.

That's gradient descent. The gradient is the slope; the learning rate eta is your step size.

Notice the steps naturally get smaller near the bottom because the slope flattens out.

The Learning Rate Matters

Typical starting values: 0.1 for SGD, 0.001 for Adam. If the loss explodes, lower it; if it barely moves, raise it.

The learning rate is the most important hyperparameter.

Too small: you creep along and training takes forever. Just right: steady progress to the bottom. Too large: you overshoot, bounce from side to side, and can even fly off with the loss exploding.

Rules of thumb: start with about 0.1 for SGD and 0.001 for Adam. If the loss explodes or shows NaN, lower it. If it barely moves, raise it.

How much data do we use to compute each step?

Batch gradient descent uses all the data for every step: accurate, smooth path, but slow and memory-hungry with millions of examples.

Stochastic gradient descent uses one example per step: very fast but noisy. See the zig-zag path.

Mini-batch, typically 32 to 256 examples, is the best of both and what everyone uses. When people say "SGD" in practice they usually mean mini-batch. The bit of noise even helps escape poor spots in the landscape.

Momentum: A Ball Rolling Downhill

Plain SGD forgets the past at every step. Momentum keeps a running "velocity" — an average of past gradients:

$$v \leftarrow \beta\, v + (1-\beta)\, g$$
$$w \leftarrow w - \eta\, v$$

$g$ = current gradient, $\beta \approx 0.9$ = how much of the past to remember

Like a heavy ball: it builds speed in consistent directions and smooths out the zig-zags.

Plain SGD only looks at the current slope. Momentum adds memory: it keeps a running average of recent gradients, like velocity.

Picture a heavy ball rolling downhill. It builds speed on long consistent slopes and doesn't get knocked around by every little bump.

Beta, typically 0.9, controls how much past gradients count. The result is faster progress and less zig-zagging.

RMSProp: A Custom Step Size for Every Weight

$$s \leftarrow \beta\, s + (1-\beta)\, g^2 \qquad\qquad w \leftarrow w - \frac{\eta}{\sqrt{s} + \epsilon}\, g$$
  • $s$ tracks a running average of squared gradients — how big this weight's gradients usually are
  • Weights with big, jumpy gradients → divide by a big number → smaller steps
  • Weights with tiny gradients → divide by a small number → bigger steps
  • $\epsilon \approx 10^{-8}$ just prevents dividing by zero; $\beta \approx 0.9$

Like adjusting your stride to the terrain: careful, small steps on steep, rocky ground; long strides on flat ground.

RMSProp solves a different problem: different weights need different step sizes.

It keeps a running average of each weight's squared gradients, a measure of how big and jumpy its gradients usually are. Then it divides the step by the square root of that.

So weights with big, noisy gradients take smaller, careful steps, and weights with tiny gradients take bigger steps. Epsilon is just a tiny number to avoid dividing by zero.

Hiking analogy: small careful steps on steep rocky ground, long strides on flat ground.

Adam = Momentum + RMSProp

$$m \leftarrow \beta_1 m + (1-\beta_1)\, g \quad\text{(momentum: direction)}$$
$$v \leftarrow \beta_2 v + (1-\beta_2)\, g^2 \quad\text{(RMSProp: scale)}$$
$$\hat m = \frac{m}{1-\beta_1^t}, \quad \hat v = \frac{v}{1-\beta_2^t} \quad\text{(bias correction)}$$
$$w \leftarrow w - \eta\,\frac{\hat m}{\sqrt{\hat v} + \epsilon}$$

Default settings (work well almost always)

  • $\eta = 0.001$
  • $\beta_1 = 0.9$ — memory for gradients
  • $\beta_2 = 0.999$ — memory for squared gradients
  • $\epsilon = 10^{-8}$

Bias correction: $m$ and $v$ start at 0, so early averages are too small; dividing by $(1-\beta^t)$ fixes this for the first few steps $t$.

Adam knows which way to go (momentum) and how big a step each weight should take (RMSProp). It's the go-to default optimizer.

Adam (short for Adaptive Moment Estimation) combines both ideas. m is the momentum term, which gives the direction. v is the RMSProp term, which gives the step size per weight.

Bias correction: m and v start at zero, so their early values are too small. Dividing by 1 minus beta to the power t boosts them during the first steps. After a while this correction fades away.

The default settings (learning rate 0.001, beta1 0.9, beta2 0.999) work well for most problems out of the box. That's why Adam is the default choice for most people.

Summary: SGD is the simple baseline. SGD with momentum is still popular for computer vision with a learning-rate schedule and can generalise very well. RMSProp is good for recurrent networks. Adam is the default first choice.

The picture shows a long narrow valley. SGD zig-zags across it; Adam heads almost straight for the minimum because it adapts the step for each direction.

Putting It All Together

Let's zoom out and connect everything we've seen.

The Big Picture

This one diagram is the whole session.

We start with data: features and labels. A model makes predictions. The loss measures how wrong they are. Backpropagation computes gradients using the chain rule. The optimizer updates the weights. We repeat this training loop until the loss stops improving.

Finally we evaluate on test data: MSE or RMSE for regression, precision, recall and F1 for classification. Hyperparameters are tuned along the way using the validation set.

Glossary

  • Feature — an input variable (x)
  • Label — the answer to predict (y)
  • Regression — predict a number
  • Classification — predict a category
  • Loss — how wrong the model is
  • Weight / bias — learned parameters
  • Hidden layer — layer between input and output that learns new features
  • Activation — adds non-linearity (ReLU, sigmoid)
  • Softmax — scores → probabilities that sum to 1
  • Epoch — one pass over all training data
  • Batch — examples per weight update
  • Gradient — slope of the loss for a weight
  • Backprop — computing gradients backwards
  • Learning rate — step size
  • Overfitting — memorising instead of learning
  • Precision — trust in a "yes"
  • Recall — share of real "yes" cases found
